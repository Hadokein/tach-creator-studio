# Tach Creator Studio 4.5

Распакуй архив, загрузи его содержимое в корень уже подключённого к Render репозитория и сохрани коммит в ветке деплоя. Открой прежний адрес сайта после автодеплоя.

## Что откроется

На главной появится публичный профиль @vladislove с датированным снимком статистики из архива. Studio сама начнёт проверку свежих данных. Для другого автора нажми на ник вверху и введи публичный ник Tach. Календарь и идеи версии 4.3 остаются доступны в том же браузере на прежнем домене.

Встроенный режим запускается без переменных окружения. Точка входа остаётся app:app, зависимости ставятся через requirements.txt. Поддерживается также запуск python app.py. Если на сервисе уже настроена рабочая DATABASE_URL из версии 4.4, он продолжит использовать эту базу и сохранённую в ней историю.

## Где хранится история

В открытой Studio свежие посты проверяются примерно раз в час, при первом сборе за день выполняется полный обход. Время у карточки показывает момент фактического замера. Снимки сначала сохраняются во временной базе сервиса, а при открытой странице копируются в IndexedDB браузера. После перезапуска Render полученная устройством история снова появляется на прежнем адресе в том же браузере. Очистка данных сайта удаляет локальную копию. CSV можно скачать в разделе «Инструменты».

Для профилей из profiles.txt в архив включён почасовой сбор через GitHub Actions. По умолчанию там @vladislove. Добавленный через интерфейс профиль сразу доступен для просмотра. Если нужна его круглосуточная история даже при спящем Render, добавь ник отдельной строкой в profiles.txt. Фоновый workflow хранит промежуточные снимки в кэше Actions и примерно раз в сутки коммитит в репозиторий history.json.gz с историей за последние 90 дней. Render получает её с автодеплоем. Срок хранения в браузере зависит от свободного места и настроек устройства.

Сам сайт работает и при выключенных Actions. Для фонового сбора папка .github/workflows из архива должна попасть в основную ветку GitHub. В репозитории должны быть разрешены Actions и запись штатным GITHUB_TOKEN в эту ветку. Секрет для встроенного режима не нужен. Ограничения владельца репозитория и правила защищённой ветки могут запретить автоматическую запись. В таком случае локальные замеры на сайте продолжаются, а причину остановки фоновой публикации покажет журнал GitHub Actions.

Версия 4.5 начинает встроенную историю со снимка в архиве и новых публичных замеров. Если на 4.3 уже накопилась нужная история SQLite, выгрузи старый CSV до деплоя.
