Tach Creator Studio 4.0
=======================

УСТАНОВКА
Замените в корне репозитория GitHub app.py, index.html и (при необходимости)
requirements.txt. На Render дождитесь Live после деплоя.

ЧТО ИЗМЕНИЛОСЬ
- Публичные публикации типов 4 (посты), 5 (видео) и 6 (трансляции).
- Убрана лишняя фильтрация по markers__in=[2], которая исключала часть записей.
- Подробности публикаций: при необходимости GET /api/v1/usercontent/{uuid}/.
- Счётчики публикации: GET /api/v1/counters/usercontent/{uuid}/.
- В разделе «Контент» можно нажать запись: обложка, описание, текущий итог,
  индивидуальная таблица изменений по датам на основании SQLite snapshots.
- Добавлен маршрут /api/analytics/post/{uuid}?profile=nickname.
- Сохранены графики главной страницы, календарь, идеи, переключение профилей.
- Старая база SQLite обновляется при первом запуске, удалять её не нужно.

ТОЧНОСТЬ
Первый замер — база сравнения. Прирост между измерениями нельзя выдавать
за реальное время каждого просмотра. Если прошло два дня, весь прирост
относится к двухдневному интервалу, а не к одному календарному дню.

ХРАНЕНИЕ И РАСПИСАНИЕ
Для сохранения истории между деплоями нужна постоянная SQLite база: например,
переменная DATABASE_PATH указывает на подключённый Render Persistent Disk.
Если диск отсутствует, данные на эфемерной файловой системе могут пропасть.
При открытии аналитики выполняется обновление (ограничено REFRESH_SECONDS),
но без внешнего планировщика приложение не собирает данные автоматически
в закрытой вкладке. Существующий защищённый маршрут /api/analytics/cron
при наличии CRON_SECRET позволяет запускать замеры для стандартного профиля.
Для других авторов автоматическое расписание нужно конфигурировать отдельно.

ВАЖНО
Публичный API Tach не гарантирован как стабильный контракт.
Экспериментальная форма входа через Tach сохранена из предыдущих версий,
но её успешная работа не подтверждена (Tach ранее возвращал HTTP 403).
Не передавайте токены и SMS-коды третьим лицам.
